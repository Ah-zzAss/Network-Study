# 3.2 다중화와 역다중화

다중화와 역다중화는 모든 컴퓨터 네트워크에서 필수적인 기능입니다.

## 1. 트랜스포트 계층의 데이터 전달 방법

### **역다중화 (Demultiplexing)**
트랜스포트 계층 세그먼트의 데이터를 올바른 소켓으로 보내는 작업입니다.
- 각 세그먼트에는 역다중화를 위한 **필드 집합**이 포함되어 있습니다.
- 수신 측 트랜스포트 계층은 수신 소켓을 식별하기 위해 이 필드들을 검사합니다.
- 검사 후 해당 세그먼트를 적절한 소켓으로 전달합니다.

### **다중화 (Multiplexing)**
출발지 호스트에서 소켓으로부터 데이터를 모으고, 각 데이터에 헤더 정보를 추가하여 캡슐화한 뒤 네트워크 계층으로 전달하는 작업입니다.
- 여기서 추가된 헤더 정보는 나중에 수신 측의 역다중화 과정에서 사용됩니다.

> ### 💡 소켓(Socket)이란?
> - 프로세스가 네트워크로 데이터를 주고받는 **출입구** 역할을 합니다.
> - 호스트의 트랜스포트 계층은 중간 매개자인 소켓에게 데이터를 전달합니다.
> - 수신 측 프로세스에는 여러 개의 소켓이 존재할 수 있으며, 각 소켓은 **유일한 식별자**를 가집니다. (식별자 포맷은 UDP와 TCP에 따라 다름)

---

## 2. 실제 다중화와 역다중화 수행 방법

트랜스포트 계층 다중화의 두 가지 요구사항은 다음과 같습니다.
1. 소켓은 **유일한 식별자**를 가져야 합니다.
2. 각 세그먼트는 목적지 소켓을 가리키는 **특별한 필드**를 가져야 합니다.
    - **특별한 필드:** 출발지 포트 번호 필드, 목적지 포트 번호 필드
    - TCP는 이 외에 추가적인 필드를 더 가집니다.

> **출발지 포트 번호의 목적:** 수신 호스트가 송신 측으로 다시 응답 데이터를 보낼 때, 응답의 목적지 포트 번호로 사용하기 위해 필요합니다.

---

## 3. 비연결형 다중화와 역다중화 (UDP)

UDP 소켓은 **[목적지 IP 주소, 목적지 포트 번호]** 두 가지 요소에 의해 식별됩니다.

### **동작 과정 (호스트 A → 호스트 B)**
1. **호스트 A의 트랜스포트 계층:** 세그먼트 생성
   - 구성: 앱 데이터 + 출발지 포트(19157) + 목적지 포트(48428) 등
2. **네트워크 계층 전달:** 생성된 세그먼트를 IP 데이터그램으로 캡슐화합니다.
3. **전송:** IP 데이터그램을 최선형 전달 서비스로 수신 호스트 B에 전달합니다.
4. **호스트 B의 역다중화:** 세그먼트 내부의 목적지 포트 번호(48428)를 검사하여 적절한 소켓으로 데이터를 보냅니다.

---

## 4. 연결지향형 다중화와 역다중화 (TCP)

TCP 소켓은 **[출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트]**의 4개 요소(4-tuple)로 식별됩니다.

### **동작 과정**
1. **서버 대기:** TCP 서버 애플리케이션은 포트 번호 12000번에서 클라이언트의 연결 요청을 기다리는 '환영 소켓'을 가집니다.
2. **클라이언트 요청:** TCP 클라이언트는 소켓을 생성하고 연결 설정 요청 세그먼트를 보냅니다.
3. **서버 수신:** 서버 OS가 목적지 포트 12000을 포함한 세그먼트를 수신하면, 이를 해당 포트에서 기다리는 서버 프로세스로 보냅니다.
4. **연결 수락 및 소켓 생성:** 서버는 연결을 수락하며 위 4가지 요소가 결합된 새로운 소켓을 생성합니다. 이후 해당 4가지 요소가 일치하는 모든 세그먼트는 이 특정 소켓으로 역다중화됩니다.

---

## 5. 웹 서버와 TCP

연결 소켓과 프로세스가 항상 1:1로 대응되는 것은 아닙니다.
- **고성능 웹 서버:** 보통 하나의 프로세스만 사용하며, 각 클라이언트 연결마다 새로운 **연결 소켓과 함께 새로운 스레드**를 생성하여 처리합니다.
- **지속적 HTTP (Persistent HTTP):** 클라이언트와 서버가 동일한 서버 소켓을 통해 여러 HTTP 메시지를 교환합니다.
- **비지속적 HTTP (Non-persistent HTTP):** 매 요청/응답마다 새로운 TCP 연결을 생성하고 종료합니다.
