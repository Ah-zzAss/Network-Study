# 3.7 TCP 혼잡 제어

네트워크 혼잡도에 따라 각 송신자가 연결에 트래픽을 보내는 전송률을 스스로 제한하도록 하는 메커니즘입니다.
* **핵심 원리:** TCP 송신자는 자신과 목적지 간의 경로에 혼잡이 없음을 감지하면 송신률을 높이고, 혼잡이 감지되면 송신률을 낮춥니다.

---

### 1. 송신자는 자신의 전송률을 어떻게 제한하는가?
송신자와 수신자는 초반 연결 시 몇 가지 변수와 송수신 버퍼를 구성합니다. 이때 송신자는 **혼잡 윈도(cwnd, Congestion Window)**라는 추가적인 상태 변수를 유지하고 추적합니다.

* **혼잡 윈도(cwnd):** TCP 송신자가 네트워크로 트래픽을 전송할 수 있는 속도에 제약을 가하는 변수입니다.
* **동작 방식:** 매 RTT(왕복 시간)가 시작될 때 송신자는 `cwnd` 바이트만큼 데이터를 전송할 수 있으며, RTT가 끝나는 시점에 해당 데이터에 대한 확인 응답(ACK)을 수신합니다.
* **전송 속도:** 송신자의 송신 속도는 대략 **cwnd / RTT (바이트/초)**가 됩니다. 송신자는 이 `cwnd` 값을 조절하여 전송률을 제한합니다.

---

### 2. 송신자는 경로의 혼잡을 어떻게 감지하는가?
TCP 송신자는 다음과 같은 상황이 발생했을 때 **손실 이벤트(Loss Event)**가 발생했다고 정의하고 혼잡을 감지합니다.

1. **타임아웃(Timeout):** 패킷에 대한 ACK가 일정 시간 내에 도착하지 않는 경우.
2. **3개의 중복 ACK 수신:** 수신자로부터 동일한 번호의 ACK를 3번 더 받는 경우.

> **혼잡 발생 흐름:** 과도한 혼잡 발생 → 라우터 버퍼 오버플로로 데이터그램 폐기 → 송신 측 손실 이벤트 발생 → 송신자가 네트워크 혼잡 인지

---

### 3. 혼잡을 감지함에 따라 어떤 알고리즘을 사용하는가?
송신자는 **TCP 혼잡 제어 알고리즘**을 통해 상태를 관리하며, 크게 3가지 단계로 구성됩니다.

1. **슬로 스타트 (Slow Start):**
   * 연결 초기나 손실 이후에 사용됩니다.
   * ACK를 받을 때마다 `cwnd`를 1씩 늘려, 결과적으로 매 RTT마다 `cwnd`가 **2배씩 지수적으로 증가**합니다.
2. **혼잡 회피 (Congestion Avoidance):**
   * `cwnd`가 임계값(`ssthresh`)에 도달하면 진입합니다.
   * 혼잡을 예방하기 위해 매 RTT마다 `cwnd`를 1 MSS씩 **선형적으로 완만하게 증가**시킵니다.
3. **빠른 회복 (Fast Recovery) - 선택 사항:**
   * '3개의 중복 ACK'를 받았을 때 수행합니다.
   * `cwnd`를 절반으로 줄인 후 선형적으로 다시 증가시키며, 타임아웃보다 빠르게 전송률을 회복합니다.

---

### 4. 주요 TCP 버전
리노는 매 RTT마다 1씩 일정하게(선형) 올리고, 큐빅은 3차 함수 곡선을 이용해 상황에 맞춰 가변적으로 올립니다.

* **TCP 리노 (TCP Reno):** 슬로 스타트, 혼잡 회피, 빠른 회복을 모두 사용하여 **AIMD**(가산 증가/승산 감소) 방식의 톱니바퀴형 그래프를 보입니다.
* **TCP 큐빅 (TCP CUBIC):** 현대 운영체제의 표준입니다. 마지막 손실 시점으로부터의 시간을 기준으로 **3차 함수**를 사용하여 `cwnd`를 조절, 대역폭을 더 효율적으로 사용합니다.
