# 3.1 트랜스포트 계층 서비스 및 개요

트랜스포트 계층 프로토콜은 각기 다른 호스트에서 동작하는 **애플리케이션 프로토콜 간의 논리적 통신**을 제공합니다.

> **💡 논리적 통신이란?**
> 애플리케이션 관점에서 보면 프로세스들이 동작하는 호스트들이 서로 직접 연결된 것처럼 보이는 것을 의미합니다.

---

## 데이터가 전달되는 과정

1. 애플리케이션 프로세스로부터 수신한 메시지를 작은 조각인 **트랜스포트 계층 세그먼트**로 분할
2. 각각의 조각에 **헤더**를 추가
3. 송신 측의 종단 시스템에 있는 **네트워크 계층**으로 세그먼트 전달
4. 네트워크 계층에서 세그먼트를 **네트워크 계층 패킷(데이터그램)** 안에 캡슐화
5. 목적지로 전달

> **📌 Note**
> * 네트워크 라우터는 오직 데이터그램의 **네트워크 계층 필드**에 대해서만 동작합니다. (데이터그램 내부에 캡슐화된 트랜스포트 계층 세그먼트 필드는 조사하지 않음)
> * 네트워크 애플리케이션에는 **하나 이상의 트랜스포트 계층 프로토콜** 사용이 가능합니다. (예: 인터넷은 UDP와 TCP를 모두 제공)

---

## 3.1.1 트랜스포트 계층과 네트워크 계층 사이의 관계

| 계층 | 통신 대상 | 주요 역할 |
| :--- | :--- | :--- |
| **트랜스포트 계층** | **프로세스** | 각기 다른 호스트에서 동작하는 프로세스들 사이의 논리적 통신 제공 |
| **네트워크 계층** | **호스트** | 호스트들 사이의 논리적 통신 제공 |

---

## 3.1.2 인터넷 트랜스포트 계층의 개요

### 트랜스포트 계층 프로토콜 (패킷: 세그먼트)
* **UDP (User Datagram Protocol):** 비신뢰적, 비연결지향형 서비스를 요청한 애플리케이션에게 제공
* **TCP (Transmission Control Protocol):** 신뢰적, 연결지향형 서비스를 요청한 애플리케이션에게 제공

### 네트워크 계층 프로토콜 (패킷: 데이터그램)
* **IP (Internet Protocol):** 호스트들 간에 논리적 통신을 제공하는 **최선형 전달 서비스(Best-effort Delivery)**

**IP 서비스의 한계점:**
* 세그먼트의 전달을 최대한 노력하지만 **보장하지 않음**
* 세그먼트의 **순서를 보장하지 않음**
* 세그먼트 내부 데이터의 **무결성을 보장하지 않음**

---

### UDP와 TCP의 주요 특징 비교

**공통점**
* **다중화와 역다중화:** 호스트 대 호스트 전달을 프로세스 대 프로세스 전달로 확장하는 기본 기능
* **무결성 검사 제공:** 헤더에 오류 검출 필드를 포함

**TCP의 추가 기능 (신뢰적인 데이터 전송)**
* 흐름 제어, 순서 번호, 확인 응답, 타이머를 이용하여 데이터가 순서대로 정확하게 전달되도록 보장
* **혼잡 제어**를 사용하여 과도한 양의 트래픽을 조절하여 네트워크 혼잡을 방지
