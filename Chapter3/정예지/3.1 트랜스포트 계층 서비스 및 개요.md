# 3.1 트랜스포트 계층 서비스 및 개요

트랜스포트 계층 프로토콜은 각기 다른 호스트에서 동작하는 **애플리케이션 프로토콜 간의 논리적 통신**을 제공한다.

> * 논리적 통신: 애플리케이션 관점에서 보면 **프로세스들이 동작하는 호스트**들이 직접 연결된 것처럼 보인다는 것을 의미

### 데이터가 전달되는 과정
1. 애플리케이션 프로세스로부터 수신한 메세지를 작은 조각인 트랜스포트 계층 세그먼트으로 분할
2. 각각의 조각에 헤더를 추가
3. 송신 측의 종단 시스템에 있는 네트워크 계층으로 세그먼트 전달
4. 네트워크 계층에서 세그먼트는 네트워크 계층 패킷 (데이터그램) 안에 캡슐화
5. 목적지로 전달

### Note
- 네트워크 라우터는 오직 데이터그램의 네트워크 계층 필드에 대해서만 동작한다
    (데이터그램 내부에 캡슐화된 트랜스포트 계층 세그먼트 필드를 조사하지 않음)
- 네트워크 애플리케이션에는 하나 이상의 트랜스포트 계층 프로토콜 사용 가능
    (인터넷은 UDP와 TCP를 가지고 있다.)

## 3.1.1 트랜스포트 계층과 네트워크 계층 사이의 관계

- 트랜스포트 계층 프로코콜: 각기 다른 호스트들에서 동작하는 프로세스들 사이의 논리적 통신을 제공
- 네트워크 계층 프로토콜: 호스트들 사이의 논리적 통신을 제공

## 3.1.2 인터넷 트랜스토프 계층의 개요

- 트랜스포트 계층 프로토콜 (패킷: 세그먼트)
    1. UDP (User Datagram Protocol): 비신뢰적, 비연결지향형 서비스를 요청한 애플리케이션에게 제공
    2. TCP (Transmission Control Protocol): 신뢰적, 연결지향형 서비스를 요청한 애플리케이션에게 제공
- 네트워크 계층 프로토콜 (패킷: 데이터그램)
    1. IP (Internet Protocol): 호스트들 간에 논리적 통신을 제공하는 최선형 전달 서비스
        - 세그먼트의 전달을 노력하지만 보장하지 않는다
        - 세그먼트의 순서를 보장하지 않는다
        - 세그먼트 내부 데이터의 무결성을 보장하지 않는다

- UDP, TCP의 기본적인 기능: 트랜스포트 계층 다중화와 역다중화 (호스트 대 호스트 전달 => 프로세스 대 프로세스 전달)

- UDP, TCP의 공통점: 헤더에 오류 검출 필드를 포함 -> 무결성 검사를 제공
- TCP: 신뢰적인 데이터 전송을 제공
    - 흐름 제어, 순서 번호, 확인 응답, 타이머를 이용하여 데이터가 순서대로 정확하게 전달되도록 한다.
    - 혼잡 제어를 사용하여 과동한 양의 트래픽을 조절
