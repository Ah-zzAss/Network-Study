# 3.3 비연결형 트랜스포트: UDP

### UDP가 선호되는 경우

1. 애플리케이션에서 무슨 데이터/언제 보낼지 더 정교하게 제어할 수 있다.
    - 지나치게 지연되는 세그먼트 전송을 원하지 않을 때 
    - 조금의 데이터 손실은 허용하는 경우
    - (애플리케이션 자체에서 신뢰성을 제공한다면 UDP도 신뢰적인 데이터 전송이 가능하다.)
2. 연결 설정이 없다.
    - TCP는 3-way-handshake를 진행한다.
    - UDP는 연결을 설정하기 위한 어떠한 지연도 없다
3. 연결 상태가 없다.
    - TCP는 종단 시스템에서 연결 상태를 유지한다.,
    - UDP는 연결 상태를 유지하지 않으며, 어떤 것도 기록하지 않는다
    - UDP에서 동작할 때 좀 더 많은 active client를 수용할 수 있다.
4. 작은 패킷 오버헤드
    - TCP는 세그먼트마다 20바이트의 헤더 오버헤드를 갖는다.
    - UDP는 세그먼트마다 8바이트의 헤더 오버헤드를 갖는다.

### UDP 세그먼트 구조

- UDP 데이터그램 데이터 필드에는 애플리케이션 데이터가 위치한다.
- UDP 데이터그램 헤더는 2바이트씩 구성된 4개의 필드를 갖는다.
    1. 출발지/목적지 포트 번호: 역다중화를 수행하는 프로세스에게 애플리케이션 데이터를 넘기게 해준다.
    2. 체크섬: 세그먼트에 오류 발생 여부를 검사하기 위해 수신 호스트가 사용한다.
    3. 길이

#### (1) 체크섬

세그먼트가 출발지로부터 목적지로 이동했을 때, UDP 세그먼트 안의 비트에 대한 변경 사항이 존재하는지 검사하는 것이다.

- 사용 목적: 오류 검출
- 사용 이유: 출발지와 목적지 사이에 모든 링크가 오류 검사를 제공한다는 보장이 없기 때문이다.
- 오류 회복을 위한 어떠한 일도 하지 않는다.
    - 일부 UDP에서는 손상된 세그먼트를 그냥 버린다.
    - 또다른 UDP에서는 경고와 함께 손상된 세그먼트를 애플리케이션에게 넘겨준다.
