### IPv4 주소체계

호스트는 일반적으로 네트워크와 연결되는 하나의 링크를 가지고 이 링크를 통해 데이터그램을 보낸다.

호스트와 물리적 링크 사이의 경계를 인터페이스라고 부른다.

라우터는 링크로부터 데이터그램을 수신하여 다른 링크로 전달하므로 2개 이상의 연결된 링크가 필요하다.

이런 링크 사이의 경계 도한 인터페이스라고 하며, 각 링크마다 하나의 인터페이스를 가지고 하나의 라우터는 여러 개의 인터페이스를 가진다.

모든 호스트와 라우터는 ip 주소를 갖도록 요구한다.

#### 서브넷

각 ip 주소는 $2^{32}$개 주소를 사용할 수 있고 이 ip 주소 일부는 연결된 서브넷이 결정한다.

<img width="938" height="678" alt="image" src="https://github.com/user-attachments/assets/3caf187e-8316-4165-9053-b90e9444a15f" />

왼쪽은 233.1.1.xxx 형식의 ip주소를 가진다. 동일한 왽쪽 24비트를 사용한다.

이를 서브넷 마스크라고 부르면 /24라고 사용한다.

#### CIDR

ip주소를 두 부분으로 나눈다.

a.b.c.d/x로 나누며 x는 최상위 비트를 의미한다.

이를 해당 주소의 프리픽스 또는 네트워크 프리픽스라고 부른다.

기관 장비들의 ip 주소는 공통 프리픽스를 사용하고 나머지 비트는 기관 내부의 모든 장비를 구별하는데 사용한다.

#### 주소 블록 획득

기관의 서브넷에서 사용하기 위한 ip 주소블록을 얻기 위해 ISP와 접촉해야한다.

#### 호스트 주소 획득: 동적 호스트 구성 프로토콜

한 기관은 ISP로부터 주소 블록을 획득하여 호스트에 IP 주소를 할당한다.

수동으로 구성이 가능하지만 일반적으로 동적 호스트 구성 프로토콜(DHCP)을 더 많이 사용한다.

호스트가 IP 주소를 자동으로 얻을 수 있게 한다.

새로운 호스트가 도착할 경우 DHCP 프로토콜 4단계 과정을 거친다.

<img width="894" height="1070" alt="image" src="https://github.com/user-attachments/assets/9d6c7139-92d1-45b2-8758-f0a71c9f6388" />


#### DHCP 서버 발견

새롭게 도착한 호스트가 DHCP를 발견하는데, DHCP 발견 메시지를 사용하여 수행된다.

포트 67번으로 UDP 패킷을 보낸다. 

목적지 IP주소를 브로드캐스트 IP 주소 255.255.255.255로 설정하고 출발지 IP 주소는 0.0.0.0으로 설정한다.

서브넷에 연결된 모든 노드로 브로드캐스트 된다.

#### DHCP 서버 제공

DHCP 발견 메시지를 받은 DHCP 서버는 DHCP 제공 메시지를 응답한다.

다시 브로드캐스트 주소 255.255.255.255를 사용하여 서브넷의 모든 노르도 이 메시지를 브로드캐스트한다.

서브넷에 여러 DHCP 서버가 존재하기 때문에 최적의 위치에 있는 서버를 선택하기 위해서다

#### DHCP 요청

새롭게 도착한 클라이언트는 서버 제공자를 선택할것이고 제공자에게 파라미터 설정으로 되돌아오는 DHCP 요청 메시지로 응답할 것이다.

#### DHCP ACK

서버는 DHCP 요청 메시지에 대해 요청된 파라미터를 확인하는 DHCP ACK 메시지로 응답한다.

클라이언트가 DHCP ACK 메시지를 받으면 상호작용이 종료되고 임대기간동안 IP주소를 사용할 수 있다.만료 후에도 이 주소를 사용할 경우 갱신할 수 있는 매커니즘을 제공한다.

새로운 서브넷에 연결할 때 마다 새로운 IP 주소를 얻기 때문에 TCP 연결은 유지될 수 없다는 단점이 있다.

### 네트워크 주소 변환(NAT)

기관 내부에 장치가 늘어나면 더 큰 주소블록을 할당해야 하지만 이미 인접한 부분을 다른곳에 할당했다면 불가능해진다.

NAT 가능 라우터는 홈 네트워크와 외부 인터넷 경계에 위치한다.

홈 네트워크 장비들은 동일한 주소를 사용한다. 내부 장비들은 내부 ip로 자유롭게 통신하지만 외부 인터넷으로 나갈 때에는 내부 ip를 사용할 수 없다. 

외부 인터넷은 하나의 공인 ip만을 사용한다.

### IPv4에서 IPv6로 전환

#### 플래그 데이

모든 인터넷 장비를 끄고 IPv4에서 IPv6로 업그레이드 하는 시간과 날짜를 정하는 것

#### 터널링

<img width="972" height="804" alt="image" src="https://github.com/user-attachments/assets/faabddd2-2958-4553-aa03-bbdbe47e8353" />


터널 입구의 IPv6노드가 IPv6 데이터그램을 IPv4 데이터그램의 데이터 필드 안에 집어넣는다.

터널 내부의 IPv4 라우터들은 내용이 무엇인지 모르고 일반적인 IPv4 데이터그램으로 인식하고 목적지까지 전달한다.

터널 출구의 IPv6 노드가 IPv4 패킷을 받아 헤더를 제거하고 원래 IPv6 데이터그램을 추출하여 목적지로 전달한다.
