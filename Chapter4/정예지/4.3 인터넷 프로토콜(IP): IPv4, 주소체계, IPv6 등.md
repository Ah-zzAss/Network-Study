## 4.3 인터넷 프로토콜(IP): IPv4, 주소체계, IPv6 등

## TCP/IP는 트랜스포트 계층과 네트워크 계층에서 오류 검사를 수행하는 이유

네트워크 계층과 트랜스포트 계층은 오류를 검사하는 범위가 다르다.

1. **네트워크 계층 (IP)**
- IPv4는 IP 헤더 체크섬으로 IP 헤더 오류를 검사한다.
- 라우터도 이 계층에서 패킷을 처리한다.
2. **트랜스포트 계층(TCP, UDP)**
- TCP와 UDP는 체크섬으로 헤더와 데이터의 오류를 검사한다.
- 송신 호스트에서 수신 호스트까지 종단 간 오류를 확인한다.

> - IPv6에서는 라우터의 처리 부담을 줄이기 위해 IP 헤더 체크섬이 제거되었다.

## IPv4 주소 체계

IPv4 주소는 호스트나 라우터 자체가 아니라 네트워크 인터페이스에 할당되는 32비트 주소이다.

- 호스트는 일반적으로 네트워크와 연결되는 하나의 링크를 갖는다.
- 호스트가 데이터그램을 보낼 때 해당 링크를 통해 데이터그램을 전달한다.
- 하나의 라우터는 여러 링크와 연결되므로 여러 개의 인터페이스를 갖는다.

> 인터페이스: 호스트 또는 라우터와 물리적 링크 사이의 경계이다.

#### 서브넷
서브넷은 라우터를 거치지 않고 서로 직접 통신할 수 있는 인터페이스들의 집합이다.

- 서브넷을 구분하려면 호스트와 라우터의 인터페이스를 분리하여 각각의 고립된 네트워크를 확인한다.
    - 고립된 네트워크의 종단점은 각 인터페이스가 된다.
    - 이렇게 분리된 각각의 네트워크를 서브넷이라고 한다.

## CIDR (Classless Inter-Domain Routing)
서브넷 주소 체계 표기를 일반화한 인터넷 주소 할당 방식

- 네트워크 부분의 길이를 자유롭게 지정할 수 있도록 일반화한 인터넷 주소 할당 방식
- (CIDR 전) 클래스 주소 체계: IP 주소의 네트워크 부분을 8, 16, 24로 제한했고 각각 고정된 A,B,C 클래스 네트워크로 분류

## 한 기관에서 호스트를 위한 주소 블록 휙득 방식 및 장비에 할당

기관은 일반적으로 ISP로부터 IP 주소 블록을 할당받는다.

- ISP는 자신이 보유한 주소 블록의 일부를 기관에 제공한다.
- 기관은 할당받은 주소 블록을 여러 서브넷으로 나누어 사용한다.
- 각 장비의 인터페이스에는 정적 설정이나 DHCP를 통해 IP 주소를 할당한다.

## DHCP (Dynamic Host Configuration Protocol)

호스트가 IP 주소와 네트워크 설정을 자동으로 할당받기 위한 프로토콜

- 클라이언트 - 서버 방식으로 동작한다.
- 별도의 수동 설정 없이 네트워크에 연결할 수 있어 플러그 앤 플레이 프로토콜 또는 제로 구성 프로토콜이라고도 한다.
- 새롭게 네트워크에 연결된 호스트는 DHCP 서버로부터 IP 주소 등의 설정 정보를 받는다.
- DHCP의 4단계 과정
    1. DHCP Discover  
        클라이언트가 DHCP 서버를 찾는다.
    2. DHCP Offer
        DHCP 서버가 사용 가능한 IP 주소를 제안한다.
    3. DHCP Request
        클라이언트가 사용할 IP 주소를 요청한다.
    4. DHCP ACK
        DHCP 서버가 IP 주소 할당을 승인한다.

- 이동성 측면에서의 단점: 
    - 노드가 서브넷에 연결하고자 할 때마다 새로운 IP주소를 DHCP로부터 얻는다.
    - 따라서 이동 노드가 서브넷 사이를 이동할 때 원격 애플리케이션에 대한 TCP 연결은 유지될 수 없다

## NAT (Network Address Translation)
사설 네트워크 내부의 여러 장비가 하나의 공인 IP 주소를 공유하도록 하는 기술

- 외부에서는 사설 네트워크 전체가 하나의 공인 IP 주소를 가진 하나의 장비처럼 보인다.

## IPv4 -> IPv6로의 전환

1. **플레그 데이 선언**  
    - 모든 장비를 특정 시점에 중단한 뒤 동시에 IPv6로 전환하는 방식이다.
    - 현실적으로 불가능하다.
2. **터널링**  
    - 두 IPv6 라우터 사이에 있는 IPv4 라우터들을 터널이라고 한다.
    - IPv6 데이터그램을 IPv4 데이터그램 내부에 넣어 터널을 통과시킨다.
    - 반대편 IPv6 라우터에서 IPv4 헤더를 제거하고 원래의 IPv6 데이터그램을 꺼낸다.
