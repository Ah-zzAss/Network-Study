## 4.2 라우터 내부에는 무엇이 있을까?

## 입력포트에서의 처리

1. **라인종단 기능**
물리계층에서 입력 링크로 들어온 전기/광신호를 bit로 변환

2. **링크 계층 처리**
링크 계층에서 이더넷 프레임의 헤더 및 오류를 처리 + 내부의 IP 데이터그램 추출

3. **검색**
네트워크 계층에서 수행되는 라우터 동작의 핵심이다.
- 검색을 통해 IP 목적지 주소로 포워딩 테이블을 조회하여 출력 포트를 결정한다.

> - 포워딩 테이블 -> 라우팅 프로세스에서 계산/갱신 or 원격 SDN 컨트롤러로부터 전달받는다.
> - 포트: 네트워크 인터페이스의 물리 포트

- **최장 프리픽스 매치 규칙**: 라우터는 패킷의 IP 주소를 포워딩 테이블의 prefix entry와 비교한다.
    - 다수의 매치가 있을 경우 가장 긴 매치 엔트리를 선택한다.
    - 선택된 엔트리와 연결된 출력 인터페이스로 패킷을 보낸다.

- **매치 플러스 액션**: 패킷 헤더의 특정 값과 규칙을 매치한 뒤, 해당 규칙에 지정된 동작을 수행한다.

## 스위치 구조

스위치 구조는 패킷이 입력 포트에서 출력 포트로 실제로 이동시키는 라우터 내부 구조이다.

#### 1. 메모리를 통한 교환

CPU와 메모리를 이용하여 입출력포트 간 패킷을 전달한다.

- 가장 단순한 초기의 라우터의 교환 방식이다.
- 패킷은 입력 포트에서 메모리로 복사된 뒤, 다시 출력 포트로 복사된다.
- 스위칭 과정
    1. 패킷이 입력포트로 도착한다.
    2. 입력포트가 라우팅 프로세스에게 인터럽트를 보낸다.
    3. 패킷을 프로세스 매모리에 복사한다.
    3. 라우팅 프로세스가 다음작업을 수행한다.
        - 헤더에서 목적지 주소 추출
        - 포워딩 테이블에서 적절한 출력포트 조회
        - 다음 패킷을 출력 포트의 버퍼에 복사

> - 메모리를 읽고 쓰는 과정이 필요하므로 스위칭 속도가 메모리 대역폭(메모리가 1초 동안 읽거나 쓸 수 있는 데이터의 양)에 의해 제한된다.
>   패킷 전송 속도보다 메모리가 읽고 쓰는 속도가 느리면, 라우터 전체 처리 속도도 느려진다.

#### 2. 버스를 통한 교환

입력 포트가 공유 버스를 통해 직접 출력 포트로 패킷을 직접 전송한다.

- 입력 포트는 라우팅 프로세스의 개입 없이 전송한다.
- 입력 포트는 패킷에 출력 포트를 나타내는 **스위치 내부 레이블**을 추가한 뒤 공유 버스로 전송한다.
- 모든 출력 포트가 패킷을 수신하지만, 레이블과 일치하는 출력 포트만 패킷을 유지한다. 
- 레이블은 스위치 내 버스 통과 목적에만 사용되므로, 출력 포트에서 제거된다.

> - 공유 버스에는 한 번에 하나의 패킷만 전송할 수 있으므로, 교환 속도가 버스의 대역폭에 의해 제한된다.

#### 3. 상호 연결 네트워크를 통한 교환

- 공유 버스의 대역폭 제한을 극복하는 방법
- 크로스바 스위치: N개의 입력 포트를 N개의 출력 포트에 연결하는 2N 버스로 구성된 상호 연결 네트워크이다.
    - N개의 입력 포트와 N개의 출력 포트를 연결하는 상호 연결 네트워크이다.
    - 입력 방향 버스와 출력 방향 버스가 교차하는 지점에 교차점이 존재한다.
    - 스위치 구조 컨트롤러가 필요한 교차점을 열어 입력 포트와 출력 포트를 연결한다.

> - 여러 입력 포트의 패킷이 동일한 출력 포트로 향하면 하나만 전달되고, 나머지는 대기해야한다.  
>  - 특정 출력 포트는 한 번에 하나의 패킷만 받을 수 있기 때문이다.


## 큐잉

패킷이 처리되는 속도보다 도착하는 속도가 빠르면 입력 포트 or 출력 포트의 버퍼에 큐가 형성된다.

큐가 커지면 다음과 같은 일이 일어날 수 있다.
- 큐잉 지연
- 라우터 메모리 손실
- 패킷 손실
    
> 패킷 손실은 도착 시 패킷을 저장할 수 있는 메모리가 없을 때 발생한다.

#### 입력 큐잉

스위치 구조가 패킷을 충분히 빠르게 처리하지 못하면, 입력 포트의 버퍼에 패킷이 대기하게 된다.

- **HOL(Head-of-the-Line) 차단**: 입력 큐의 맨 앞 패킷 때문에 뒤에 있는 패킷도 이동하지 못하는 현상

#### 출력 큐잉

스위치 구조에서 패킷의 속도가 출력 링크의 전송 속도보다 빠르면 -> 출력 포트에 큐가 생성된다.

- **drop-tail 정책**: 출력 버퍼가 가득 찬 상태에서 새로운 패킷 도착 시, 해당 패킷을 삭제하는 정책이다.
- 그 외 혼잡 관리 방식: 
    - 이미 대기 중인 패킷 삭제
    - 버퍼가 완전히 차기 전에 일부 패킷 삭제
    - 패킷 헤더에 혼잡 정보 표시

## 포트에 어느 정도의 버퍼가 필요할까?

버퍼는 커질수록 (패킷 손실 가능성을 찾출 수 있지만,) 큐잉 지연이 길어진다.

- **buffeerbloat(버퍼블로트)**: 패킷의 과도한 버퍼링으로 인해 생기는 패킷 교환 네트워크의 높은 대기시간이 발생하는 현상이다.

- 무조건 버퍼가 클수록 좋은 것이 아니다. 적절한 균형이 필요하다.
- ex, 혼잡하여 버퍼가 꽉 차게 되면, 패킷 손실을 위해 홉당 버퍼의 양을 10배 늘린 것이 종단간 지연을 10배 늘리게 된다. 증가된 rtt는 tcp 송신자의 초기 혼잡/패킷 손실에 대한 응답속도 도 떨어지게 된다.

## 패킷 스케줄링

출력 포트의 큐에 대기 중인 패킷 중 어떤 패킷을 먼저 전송할지 결정하는 방식이다.

1. **FCFS 또는 FIFO**  
먼저 큐에 들어온 패킷을 먼저 전송한다.
2. **우선순위 큐잉**  
패킷을 우선순위 클래스별로 구분하고, 우선순위가 높은 클래스의 패킷을 먼저 처리한다.
같은 클래스 내부에서는 일반적으로 FIFO 방식으로 처리한다.
3. **라운드 로빈 큐잉**  
패킷을 여러 클래스로 구분한 뒤, 각 클래스의 큐를 차례대로 돌아가며 하나씩 처리한다.
