# 2.3 인터넷 전자메일

인터넷 상위 레벨 개념에서의 구성 요소

- 사용자 에이전트: 사용자가 메세지를 읽고, 응답, 전달, 구성하게 해준다.
- 메일 서버: 메일 박스 관리, SMTP의 클라이언트/서버 측을 모두 수행
- SMTP: 송신자의 메일서버로 부터 수신자의 메일 서버로 전송하는데 사용하는 애플리케이션 계층 프로토콜
    - TCP 를 이용한다.
    - 메일을 보낼 때는 SMTP의 클라이언트로 동작, 메일을 받을 때는 SMTP의 서버로 동작한다.

## 2.3.1 SMTP

송신자의 메일 서버로부터 수신자의 메일 서버로 메세지를 전송한다.

- SMTP는 모든 메세지의 몸체는 7비트의 아스키 코드여야 한다는 제한이 있다.
- 지속 연결을 사용한다: 서버에 보낼 다른 메세지가 있으면 같은 TCP 연결 상에서 이어서 반복한다. 없으면 연결을 닫는다.

### 기본 동작

[앨리스가 밥에게 메일을 전달하는 상황]
1. 앨리스가 메세지 작성을 마치면 사용자 에이전트에게 메세지를 보내라고 명령한다.
2. 앨리스의 사용자 에이전트는 메세지를 앨리스의 메일 서버에 보내고, 메일 서버의 출력 메세지 큐에 메세지가 저장된다.
3. 앨리스의 메일 서버에서 동작하는 SMTP 클라이언트는 메세지 큐에 있는 메세지를 본다. 밥의 메일 서버에서 수행되고 있는 SMTP에게 TCP 연결을 설정한다.
4. 초기 SMTP 핸드셰이킹 이후에 SMTP 클라이언트는 앨리스의 메세지를 TCP 연결로 보낸다.
    - 핸드셰이킹에 SMTP 클라이언트는 송신자/수신자의 전자 메일 주소를 제공한다.
5. 밥의 메일 서버 호스트에서 SMTP 서버는 메세지를 수신한다. 밥의 메일 서버는 그 메세지를 밥의 메일 박스에 놓는다.
6. 밥은 원하는 시간에 그 메세지를 사용자 에이전트를 이용하여 읽는다.

## 2.3.2 메일 메세지 포맷

## 2.3.3 메일 접속 프로토콜

일반 사용자는 로컬 호스트에서 사용자 에이전트를 수행하고, 늘 켜져있는 공유 메일 서버에 저장된 메일박스에 접근한다.
- 메일 박스는 보통 사용자들과 공유한다.

### 사용자 에이전트가 직접 연결하지 않는 이유

사용자 에이전트는 스마트폰 앱이나 PC의 같은 프로그램,
직접 밥의 서버로 메일을 보내려다가 네트워크 문제로 실패하면, 메일은 그냥 증발하므로 중계 서버를 이용한다.

1. 앨리스의 사용자 에이전트는 앨리스의 메일 서버로 전자 메일 메세지를 SMTP 또는 HTTP를 통해서 보낸다.
2. 앨리스의 메일 서버가 SMTP를 사용하여 밥의 메일 서버로 전자 메일 메세지를 중계한다.

### 수신자의 메세지가 ISP 내부의 메일 서버에 있는 경우

- 밥의 사용자 에이전트는 메세지를 얻기 위해 SMTP를 사용할 수 없다.
- SMTP는 push 프로토콜인 반면, 메세지를 얻는 것은 pull동작이기 때문이다.

[밥이 자신의 메일을 얻는 방법]
밥이 스마트폰 앱, 웹 기반 전자메일을 사용한다면,
밥의 사용자 에이전트는 HTTP를 사용할 것이다.

1. 메일서버는 SMTP, HTTP 인터페이스를 갖고 있어야한다.
2. 전형적인 메일 크라리언트 사용, 이 경우 인터넷 메일 접근 프로토콜(IMAP)을 사용
