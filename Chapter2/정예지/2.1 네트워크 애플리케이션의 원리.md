# 2.1 네트워크 애플리케이션의 원리

네트워크 애플리케이션의 중심은 다른 위치의 종단 시스템에서 동작하고 네트워크를 통해 서로 통신하는 프로그램을 작성하는 것이다.
따라서, 우리는 새로운 애플리케이션을 만들 때 여러 종단 시스템에서 실행되는 소프트웨어를 작성해야한다.

## 2.1.1 네트워크 애플리케이션 구조

- 네트워크 구조: 애플리케이션 개발자 관점에서 고정되어 있는 것, 개발자는 애플리케이션에 특정 서비스 집합을 제공하는 역할을 한다.
- 애플리케이션 구조: 애플리케이션 개발자가 설계하는 것, 애플리케이션이 다양한 종단 시스템에서 어떻게 조직되어야하는지를 알려준다.

애플리케이션 개발자는 다음 **네트워크 애플리케이션에서 사용되는 두 구조** 중 하나를 선택하여 개발할 것이다.

- 클라이언트-서버 구조: 클라이언트가 서버에게 서비스 요청을 하면 응답을 받는 구조
    - 클라이언트는 가끔, 항상 동작하지만 서버는 항상 동작한다.
    - 클라이언트는 서로 직접적으로 통신하지 않는다
    - 서버가 고정 IP주소를 가지며, 항상 동작하므로 client는 서버 패킷을 보내어 언제든 연결 가능하다.
    - 클라이언트의 무수한 요청이 예상될 경우 데이터 센터를 통해 강력한 가상의 서버를 생성할 수 있다.
    - ex) 웹, 파일 전성, 원격 로그인, 전자메일

- P2P: 특정 서버를 통하지 않고 peer라는 간헐적으로 연결된 호스트 쌍이 서로 직접 통신하는 구조
    - peer: 서비스 제공자가 소유하지 않고 사용자가 제어하는 데스크톱, 랩톱을 말한다.
    - 항상 켜져 있는 인프라스트럭쳐 서버에 최소로 의존/거의 의존하지 않는다
    - 일반적으로 상당한 서버 인프라스트럭처와 서버 대역폭을 요구하지 않기 때문에 비용 효율적이다.

## 2.1.2 프로세스 간 통신

두 프로세스 간 통신하는 것을 보여줄 때 다음과 같이 정의할 수 있다.
(P2P 구조인 경우 송신 프로세스를 클라이언트, 수신 프로세스를 서버로 정의할 수 있다.)
- 클라이언트: 통신을 초기화하는 프로세스 (다른 프로세스와 세션을 시작하기 위해 접속을 초기화)  
- 서버: 세션을 시작하기 위해 접속을 기다리는 프로세스

2개의 종단 시스템에서 프로세스는 컴퓨터 네트워크를 통한 메세지 교환으로 서로 통신한다.
메세지 교환은 소켓을 통해 이루어진다.

### 프로세스와 컴퓨터 네트워크 사이의 인테페이스 : 소켓
호스트의 애플리케이션 계층, 트랜스포트 계층 간의 인터페이스

- 네트워크 애플리케이션이 인터넷에 만든 프로그래밍 인터페이스
- 애플리케이션, 네트워크 간의 API라고도 한다.
- 애플리케이션 개발자는 소켓의 애플리케이션 계층에 대한 모든 통제권을 갖는다.
- 애플리케이션 개발자는 소켓의 트랜스포트 계층에 대한 통제권은 거의 갖지 못한다.
    - 트랜스포트 프로토콜 선택
    - 최대 버퍼와 최대 세그먼트 크기 같은 약간의 트랜스포트 매개변수 설정

### 프로세스 주소 배정

네트워크에서 데이터를 특정 프로세스에게 전달하려면, 송신 프로세스는 수신 대상의 주소 정보를 알고 있어야 한다.

인터넷에서 목적지를 식별하기 위해서는 크게 두 가지 정보가 명시되어있어야한다.
1. 호스트의 주소
    - 인터넷에서 호스트는 IP 주소로 식별된다.
2. 목적지 호스트 내의 수신 프로세스를 명시하는 식별자
    - 목적지 포트번호를 통해 식별할 수 있다.
    - 일반적으로 한 호스트가 많은 네트워크 애플리케이션을 실행 가능하기 때문이다.

### 2.1.3 애플리케이션이 이용 가능한 트랜스포트 서비스

송신 측 애플리케이션은 소켓을 통해 메세지를 보낸다.  
그 소켓의 반대편에서 트랜스포트 프로토콜은 네트워크를 통해 그 메세지를 수신 프로세스의 소켓으로 이동시킨다.  

> * 소켓: 애플리케이션 프로세스와 트랜스포트 프로토콜 간의 인터페이스

트렌스포트 계층 프로토콜이 애플리케션에게 제공할 수 있는 서비스는 네 가지가 존재한다.
#### 1. **신뢰적 데이터 전송**
패킷들은 컴퓨터 네트워크 내에서 손실될 수 있다.

- **신뢰적 데이터 전송**: 프로토콜이 보장된 데이터 전송 서비스를 제공
    - 트렌스포트 계층 프로토콜이 이 서비스를 제공할 때 송신 프로세스는 데이터가 소켓을 통해 수신 프로세스에 도착할 것이라는 확신을 가진다.

- **손실 허용 애플리케이션**: 어느 정도의 데이터 손실을 허용한다.
    - 송신 프로세스가 보낸 데이터가 수신 프로세스로 전혀 도착하지 않을 수 있다.
    
#### 2. **처리율**

송신 프로세스가 수신 프로세스로 비트를 전달할 수 있는 비율

- 애플리케이션은 보장된 처리율을 요구할 수 있고, 트랜스포트 프로토콜은 가용한 처리율의 최소값을 보장한다.
- **대역폭 민감 애플리케이션**: 처리율 요구사항을 갖는 애플리케이션
- **탄력적 애플리케이션**: 가용한 처리율에 따라 이용할 수 있다.

#### 3. **시간**

트랜스포트 계층 프로토콜이 데이터 전송에 엄격한 시간 제한 조건을 제공하는 것

#### 4. **보안**

트랜스포트 계층 프로토콜이 애플리케이션에 하나 이상의 보안서비스를 제공할 수 있다.

- 두 프로세스 사이에 기밀성을 제공
- ex) 송신 호스트: 트랜스포트 프로토컬이 송신 프로세스가 전송하는 모든 데이터 암호화,
    수신 호스트: 트랜스포트 프로토콜이 수신 프로세스로 전달하기 전 데이터의 암호를 해독

### 2.1.4 인터넷 전송 프로토콜이 제공하는 서비스

TCP, UDP: 프로토콜이 제공하는 서비스 모델 

#### TCP 서비스

- 연결 지향형 서비스:
    - 전송 전 client-server 간 서로 전송 제어 정보를 교환하는 핸드 셰이킹 과정을 거친다.
    - 전이중연결 (full-duplex): 두 프로세스가 서로 동시에 메세지를 전송할 수 있다
- 신뢰적인 데이터 전송 서비스: 
    - 모든 데이터를 오류 없이 올바른 순서로 전달

- 혼잡제어: 각 TCP 연결이 네트워크 대역폭을 공평하게 공유할 수 있게끔 제한한다.
    - 네트워크가 혼잡상태에 이르면 프로세스의 속도를 낮춘다.
    - 통신하는 프로세스의 직접 이득보다는 인터넷 전체 성능 향상을 위한 서비스이다.

> TLS (Transport Layer Security) : TCP + 보안 서비스(암호화, 데이터 무결성, 종단 인증)

#### UDP 서비스

최소의 서비스 모델을 가진 가장 간단한 프로토콜

- 비연결형: 핸드셰이킹 과정 없음
- 비신뢰적인 데이터 전송: 수신 소켓에 메세지가 도착하는 것을 보장하지 않음, 순서도 보장하지 않음
- 혼잡제어 방식 미포함

### 2.1.5 애플리케이션 계층 프로토콜

다른 종단 시스템에서 실행되는 **애플리케이션의 프로세스가 서로 메세지를 보내는 방법**
- **애플리케이션 계층 프로코콜**은 네트워크 **애플리케이션의 한 요소**일 뿐이다.

- 애플리케이션 계층 프로토콜이 정의하는 내용
    - 교환 메세지 타입 (ex, 요청 / 응답)
    - 여러 메세지 타입의 문법 (ex, 메세지 내부의 필드/ 필드 간의 구별 방법)
    - 필드의 의미
    - 언제, 어떻게 프로세스가 메세지 전송/응답하는지 결정하는 규칙
