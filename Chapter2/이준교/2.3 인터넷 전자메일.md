# 2.3 인터넷 전자메일

(사진)

메시지 작성을 끝내면, 사용자 에이전트는 메시지를 메일 서버로 보내고, 거기서 메시지는 메일 서버의 출력 메시지 큐에 들어간다. 
메시지를 읽고 싶을 때 사용자 에이전트는 메일 서버에 있는 메일박스에서 메시지를 가져온다.

### 사용자 에이전트

사용자가 메시지를 읽고, 응답하고, 전달하고, 저장하고, 구성하게 해준다.

### 메일 서버

`메일 서버`는 전자메일 인프라스트럭처의 중심이다.

각 수신자는 메일 서버에 `메일박스`를 가지고 있다.

송신자의 서버가 수신자의 서버로 메일을 전달할 수 없다면, 송신자의 서버는 그 메시지를 `메시지 큐`에 보관하고 나중에 그 메시지를 전달하기 위해 다시 시도하며, 계속 실패하게 되면 메시지 제거 후 송신자에게 통보한다.

### SMTP

`SMTP`는 인터넷 전자메일을 위한 주요 애플리케이션 계층 프로토콜이다.

SMTP는 메일을 송신자의 메일 서버로부터 수신자의 메일 서버로 전송하는 데에 TCP의 신뢰적인 데이터 전송 서비스를 이용한다.

SMTP는 대부분의 애플리케이션 계층 프로토콜처럼, 클라이언트와 서버를 갖고 있다.

SMTP의 클라이언트와 서버 모두가 모든 메일 서버에서 수행되고, 상대 메일로 송신할 때는 클라이언트가 되고 수신할 때는 서버가 된다.

## 2.3.1 SMTP

(사진)

1. 앨리스는 전자 메일 사용자 에이전트를 수행하고, 밥의 전자 메일 주소를 제공하여 메시지를 보내라고 명령한다.

2. 앨리스의 사용자 에이전트는 메시지를 그녀의 메일 서버에게 보내고, 그곳에서 메시지는 메시지 큐에 놓인다.

3. 앨리스의 메일 서버에서 동작하는 SMTP의 클라이언트 측은 메시지 큐에 있는 메시지를 본다.
밥의 메일 서버에서 수행되고 있는 SMTP 서버에게 TCP 연결을 설정한다.

4. 초기 SMTP 핸드셰이킹 이후에 SMTP 클라이언트는 앨리스의 메시지를 TCP 연결로 보낸다.

5. 밥의 메일 서버 호스트에서 SMTP의 서버 측은 메시지를 수신한다. 밥의 메일 서버는 그 메시지를 밥의 메일 박스에 놓는다.

6. 밥은 편한 시간에 그 메시지를 읽기 위해 사용자 에이전트를 시동한다.

SMTP는 두 메일 서버가 먼 거리에 떨어져 있더라도 중간 메일 서버를 사용하지 않는다.

### SMTP가 메시지를 송신 메일 서버에서 수신 메일 서버로 전송하는 과정

1. 클라이언트 SMTP는 서버의 SMTP의 25번 포트로 TCP 연결을 설정한다. 만약 서버가 죽어있다면 나중에 시도한다.
2. 연결이 설정되면, 애플리케이션 계층 핸드셰이킹을 수행한다. 이때 SMTP 클라이언트는 송신자의 전자메일 주소와 수신자의 전자메일 주소를 제공한다.
3. 이후 클라이언트는 메시지를 보낸다.
4. 보낼 다른 메시지가 있다면 같은 TCP 연결 상에서 반복하며, 그렇지 않으면 TCP를 닫는다.

## 2.3.3 메일 접속 프로토콜

(사진)

앨리스의 사용자 에이전트는 그녀의 메일 서버로 전자메일 메시지를 SMTP 또는 HTTP를 통해 보낸다.

앨리스의 메일 서버는 SMTP를 사용하여 밥의 메일 서버로 전자메일 메시지를 중계한다.

두 단계 절차인 이유는 앨리스의 메일 서버를 통해 중계하지 않으면 앨리스의 사용자 에이전트는 메일 서버에 도달할 수 없기 때문이다. 

밥의 사용자 에이전트는 메시지를 얻기 위해 SMTP를 사용할 수 없다. SMTP는 푸시 프로토콜인 반면에 메시지를 얻는 것은 풀 동작이기 때문이다.

밥이 메일 서버로부터 전자메일을 확인하는 대표적인 방법은 (1) HTTP, (2) IMAP 이다.
